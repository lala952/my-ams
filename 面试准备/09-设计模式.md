# 09 · 设计模式

> 你的项目里有一个 `designPatterns/strategy` 包，专门写了策略模式的折扣、支付示例，这是现成的面试素材。

---

## 1. 设计模式六大原则（SOLID + 迪米特）

| 原则 | 说明 |
|------|------|
| 单一职责 SRP | 一个类只做一件事 |
| 开闭原则 OCP | 对扩展开放，对修改关闭 |
| 里氏替换 LSP | 子类能替换父类 |
| 依赖倒置 DIP | 依赖抽象，不依赖具体 |
| 接口隔离 ISP | 接口小而专 |
| 迪米特法则 | 最少知道原则，降低耦合 |

## 2. 策略模式（项目有完整代码）

### 2.1 定义
定义一组算法，把它们封装起来，让它们之间可以**互相替换**，使算法的变化独立于使用算法的客户端。

### 2.2 项目代码结构
```
designPatterns/strategy/
├── discount/
│   ├── context/DiscountContext.java          // 上下文：持有策略
│   ├── service/DiscountStrategy.java         // 策略接口
│   └── service/impl/
│       ├── FestivalDiscount.java             // 节日 7 折
│       ├── MemberDiscount.java               // 会员折扣
│       └── NewUserDiscount.java              // 新用户折扣
└── payment/
    ├── context/Order.java                    // 订单上下文
    ├── service/PaymentStrategy.java          // 支付策略接口
    └── service/impl/
        ├── AlipayStrategy.java               // 支付宝
        ├── WechatPayStrategy.java            // 微信
        └── CreditCardStrategy.java           // 信用卡
```

### 2.3 核心代码解析
```java
// 策略接口
public interface DiscountStrategy {
    double calculateDiscount(double originalPrice);
}

// 上下文：统一调用入口
public class DiscountContext {
    private DiscountStrategy strategy;
    public DiscountContext(DiscountStrategy strategy) { this.strategy = strategy; }
    public void setStrategy(DiscountStrategy strategy) { this.strategy = strategy; }
    public double getFinalPrice(double originalPrice) {
        return strategy.calculateDiscount(originalPrice);
    }
}
```

### 2.4 面试讲法
> 我在项目里用**策略模式**设计了折扣和支付两个场景：定义策略接口，每个具体折扣/支付方式是一个实现类，通过 `Context` 上下文统一调用、动态切换策略。这样新增一种支付方式或折扣，只需加一个实现类，符合**开闭原则**，避免了大量 `if-else` 分支。

### 2.5 和工厂模式结合
策略模式通常配合**工厂模式**：工厂根据参数返回具体策略对象。消除 if-else 的经典写法是"**策略模式 + 工厂 + 枚举/Map**"。

## 3. 工厂模式

- **简单工厂**：一个工厂根据参数返回不同产品。
- **工厂方法**：每个产品一个工厂，符合开闭原则。
- **抽象工厂**：生产一组相关产品。
- **结合项目**：Spring 的 `BeanFactory` 就是工厂模式；策略模式里可以用工厂创建策略对象。

---

## 4. 单例模式（必考，重点讲双重检查锁）

### 4.1 几种写法
1. **饿汉式**：类加载就创建，线程安全，可能浪费。
2. **懒汉式**：用到才创建，需加锁。
3. **双重检查锁 DCL**（推荐）：
```java
public class Singleton {
    private static volatile Singleton instance;  // volatile 防指令重排
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {                 // 第一重检查
            synchronized (Singleton.class) {
                if (instance == null) {         // 第二重检查
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```
4. **静态内部类**：利用类加载机制保证单例，最优雅。
5. **枚举**：天然防反射、防序列化破坏。

### 4.2 追问：DCL 为什么要 volatile？
> `new Singleton()` 不是原子操作（分配内存 → 初始化 → 赋值引用），指令重排可能先赋值引用再初始化。不加 volatile，另一个线程可能拿到**未初始化完的对象**。volatile 禁止这种重排。

### 4.3 追问：反射和序列化能破坏单例吗？
> 能。反射可调私有构造器，序列化反序列化会创建新对象。解决：枚举单例天然免疫。

## 5. 模板方法模式

- 父类定义算法骨架，子类实现具体步骤。
- **结合项目**：Spring 的 `JdbcTemplate`、`RestTemplate`，MyBatis-Plus 的 `ServiceImpl`/`BaseMapper` 都是模板方法思想。你的 `ChangeServiceImpl extends ServiceImpl<ChangeMapper, Change>` 就是在复用模板。

---

## 6. 代理模式

- 静态代理、JDK 动态代理、CGLIB 代理。
- **结合项目**：Spring AOP（事务、日志 `@Log`、数据权限 `@DataScope`）就是动态代理。`@Transactional` 通过代理实现事务。

---

## 7. 观察者模式

- 发布-订阅，一方状态变化通知多方。
- **结合项目**：Spring 事件监听（`ApplicationEvent` + `@EventListener`）、Nacos 配置变更推送。

---

## 8. 适配器模式

- 把不兼容的接口适配成目标接口。
- **结合项目**：Spring MVC 的 `HandlerAdapter`、`MethodArgumentResolver`。

## 附：高频面试题速答

1. **用过哪些设计模式？** — 结合项目说策略、工厂、单例、模板方法、代理、观察者。
2. **策略模式和工厂模式区别？** — 策略关注"行为可替换"，工厂关注"对象创建"；常配合使用。
3. **单例的破坏方式？** — 反射、序列化。
4. **装饰者模式和代理模式区别？** — 装饰者增强对象功能（可多层嵌套），代理控制访问。
5. **如何消除大量 if-else？** — 策略模式 + 工厂 + Map/枚举，或责任链。
6. **责任链模式应用？** — 网关过滤器链、Spring 拦截器链。
7. **开闭原则怎么理解？** — 通过新增代码扩展，不改动已有代码。
8. **建造者模式？** — `Lombok @Builder`、`StringBuilder`。
9. **享元模式？** — 池化，如 Integer 缓存、连接池。
10. **观察者和发布订阅区别？** — 观察者直接通知，发布订阅有事件总线解耦。
